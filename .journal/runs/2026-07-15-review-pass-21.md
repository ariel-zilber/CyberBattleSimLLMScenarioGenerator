# Review pass 21 — actual firewall semantics

Scope: read-only comparison of generated firewall YAML, static solvers, and the
connected CyberBattleSim actuator. Same Pass 10 artifact was rescanned.

## Main result

The actuator's firewall helper ignores peer subnet/address and returns on the
first exact port match. For the original 272 non-start credential edges:

```text
exact port+subnet policy failures: 146 / 272 = 53.7%
runtime first-port-match failures:   43 / 272 = 15.8%
policy failures runtime permits:    103
runtime missing outgoing:            42
runtime missing incoming:             2
```

The earlier 53.7% result is preserved but relabeled as policy-integrity failure,
not dynamic blocking probability.

## Consequences

- Intended edges can still fail dynamically (43 observed structurally).
- Many unintended cross-subnet edges can execute, creating shortcut risk.
- Phase 2 reachability, object BFS, the condition solver, and runtime do not use
  the same firewall graph.
- `*`/`any` is not a runtime wildcard because the actuator uses exact port
  equality.
- An object-generator block policy is defeated by its earlier emitted allow rule
  for the same port, since the actuator returns on that first match.

No source, config, tests, or generated artifact was modified.
