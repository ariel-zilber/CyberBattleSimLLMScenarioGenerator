# Review pass 18 — object-generator BFS/compiler parity

Scope: read-only review of `pipeline/object_generator` plus four minimal
in-memory reproductions. Only this journal was modified.

## Confirmed

1. BFS honors initial credentials and arbitrary initial privileges, while the
   compiler drops both.
2. Local vulnerability prerequisites are validated against the target but
   evaluated on the compiled source.
3. Remote exploits bypass BFS firewall checks and receive no compiled firewall
   authorization.
4. Probe is enabled but state-neutral, so it can never enter a shortest path.
5. A block-policy Connect compiles conflicting equal-priority allow/deny rules.
6. Search-cap exhaustion is indistinguishable from exhaustive unsolvability.
7. Mandatory-bypass analysis can miss a bypassed mandatory transition and label
   an alternate transition as mandatory.

## Evidence summary

- Initial-state case: validation true, BFS solved at depth 1, compiled pivot
  privilege 0, no compiled initial credential.
- Prerequisite case: validation true, source properties empty, compiled source
  precondition `Needed`.
- Remote-firewall case: validation true, BFS solved at depth 1, source outgoing
  and goal incoming rules both empty.
- Probe case: unsolved, minimum depth null, explored states 1.
- Block-policy case: BFS unsolved; compiled source allowed the connection and
  compiled target contained equal-priority allow and deny rules.
- Search-cap cases: a normally solvable case returned the generic unsolved shape
  for caps 0 and 1.
- Mandatory case: selected path used `AlternateFirst`; bypass report named that
  alternate and omitted `DeclaredMandatory`.
